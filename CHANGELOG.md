# Changelog

### [Unreleased] - 2026-11-11
- DVO-669: on `ORACLE`, set the hostname to the instance display name (`VPN44-dev-us-ashburn-1`), read from `169.254.169.254/opc/v2/instance/displayName`, instead of the OCID. Elastic Agent takes `host.name` from the hostname at enrolment, so VPN hosts appeared in Kibana under a truncated OCID. Other clouds, and an empty lookup, still fall back to the instance id. Registration is unaffected because it sends `$INSTANCE_ID`, not the hostname.

### [Unreleased] - 2026-11-01
- UNP-8001: fix `apt_wait` never running apt-get. It treated `unattended-upgrades.service` being active as "apt busy", but that unit only runs `unattended-upgrade-shutdown --wait-for-signal` and is active for the machine's whole life, so all 60 attempts waited and the helper gave up after 10 minutes — Docker never installed (OCI il-jerusalem-1, dev + stage). Now waits on `apt-daily`, `apt-daily-upgrade` and an actual `/usr/bin/unattended-upgrade` process.
- UNP-8001: fetch the Vault config (`kv/vpn-server/<env>`) with curl as the first step of `init-vpn-linode.sh`, before any package work and before `set -x`, into a root-only `/root/vpn-server-config.json`; parse it later with the same jq expression. The token vpn-admin passes has a ~5 minute TTL and the old read only happened after Docker/Vault/base packages were installed, which slow first boots (OCI, 1-vCPU droplets) exceeded. A failed fetch now aborts with a clear `FATAL` instead of continuing with an empty config.

### [Unreleased] - 2026-09-07
- UNP-8001: add the `ORACLE` branch to the `INSTANCE_CLOUD` dispatcher in `init-vpn-linode.sh` (reads the instance OCID from `169.254.169.254/opc/v2/instance/id` with the `Authorization: Bearer Oracle` header). Without it an OCI node prints `MISSING INSTANCE_ID`, gets an empty hostname and never reports peers.
- UNP-8001: route every apt call through a new `apt_wait` helper in `functions-2404.sh`. `-o DPkg::Lock::Timeout` only covers the dpkg locks; `apt-get update` takes `/var/lib/apt/lists/lock` via `pkgAcquire::GetLock()`, which fails immediately with no timeout option. `apt-daily.timer` is `Persistent=true` and fires at first boot, so the first apt call died, Docker and Vault never installed, and the script looped on "waiting for configurations".
- UNP-8001: open the VPN ports on the host firewall via a new `open_vpn_firewall_ports` in `functions-2404.sh`, called from `init-vpn-linode.sh`. OCI's Ubuntu images REJECT everything but 22/tcp in `/etc/iptables/rules.v4`, so 51820/udp and 443/tcp were closed on the host even with a correct VCN security list. Rules are inserted *before* the REJECT (an append would be silently dead) and persisted with `netfilter-persistent` where available; a no-op on Linode/DigitalOcean/Hetzner/AWS images. ufw is deliberately not used — Oracle documents that it can leave their instances unbootable.
- UNP-8001: shim `docker-compose` to the v2 plugin in `install_wireguard-2404.sh`. The legacy v1 download never published an aarch64 build, so on OCI Ampere shapes it 404s and writes "Not Found" into the binary path.
- UNP-8001: rewrite `ES_PREFIX` for `aarch64` in `install_elastic` so we do not extract an x86 elastic-agent on ARM shapes.
- UNP-8001: fetch the AWS instance id through IMDSv2. Canonical's Ubuntu AMIs carry `ImdsSupport=v2.0`, so instances launched from them require a token and the unauthenticated IMDSv1 GET returned 401 — leaving `INSTANCE_ID` empty, the hostname blank, and the node registering itself against an empty id (400 orphaned peer rows on stage sa-east-1, 2026-09-07). The old `VPNSERVER_V7` AMI has no `ImdsSupport` attribute, so IMDSv1 was permitted and this never surfaced. Also made the `MISSING INSTANCE_ID` check unconditional — as an `elif` it could only fire when no cloud branch matched, so an empty id from a branch that did match passed silently.

### [Unreleased] - 2026-07-01
